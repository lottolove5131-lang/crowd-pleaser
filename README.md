# Crowd Pleaser

Plan one evening out for friends with very different tastes. Each friend adds a few favorites (an artist, a movie, a restaurant, a book). Crowd Pleaser turns them into Qloo taste signals, scores every candidate dinner spot, artist and movie **separately for each friend**, and picks the option whose least-happy friend is happiest. Gemini then explains, by name, why each pick works for everyone.

## How it works
1. `/search` resolves each favorite to a Qloo entity.
2. `/v2/insights` runs once for the whole group (candidate pool) and once per friend.
3. Each candidate gets a match score per friend from that friend's ranking. Ranking key = minimum score across friends (fairness), then average.
4. Gemma 4 writes the plan from the returned rankings. If the free model service fails, the app marks its output as a ranking-template summary; it never claims the template was generated by the model.

## Run
Set the environment variables `QLOO_API_KEY` and `GEMINI_API_KEY`, then run `node server.cjs`. Open `http://127.0.0.1:8793`. The server binds only to localhost. For a public deployment, use a hosting plan whose conditions cover the intended use. Static front end in `public/`, serverless function in `api/plan.js`. No dependencies.

Rank scores are relative positions in each returned candidate list, not probabilities or measured satisfaction. Missing candidates receive zero. The selected option maximizes the minimum score, then the average score. Restaurant availability and opening hours are not checked.

Qloo calls are serialized with a minimum interval and bounded retries for HTTP 429. Public error messages do not include upstream bodies or API keys. Names and taste preferences are sent to Qloo and the model provider; use fictional names for the sample. Nothing is written to browser storage.

Run `node --test test.cjs network.test.cjs` for validation, rate-limit retry, concurrent-request rejection, explanation fallback and timeout regressions. Network tests use stubbed providers. Host evidence separately records live Qloo calls; a passing mocked test is not proof of a live integration.
